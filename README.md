# Домашние задания — веб-приложение

Приложение для выполнения ребёнком заданий по школьным предметам в браузере, с автопроверкой
и отслеживанием прогресса родителем. Работает в Docker, все данные хранятся локально.

## Новое в этой версии

- **Смена ролей после создания** — админ может в любой момент поменять роль любого пользователя
  (родитель → админ, админ → родитель и т.д.) прямо из панели администратора. Нельзя разжаловать
  последнего администратора.
- **Пароли**: у каждого пользователя есть страница «Профиль» для смены своего пароля; админ может
  сбросить пароль любому пользователю. Пароль самого админа можно сбросить и через переменную
  окружения `RESET_ADMIN_PASSWORD=true` (см. ниже) — на случай, если забыли пароль и не можете
  зайти в интерфейс вообще.
- **Библиотека заданий** — импорт задания больше не привязан жёстко к конкретному ребёнку:
  задание сначала попадает в общую библиотеку (вкладка «Библиотека заданий» у родителя), а затем
  его можно назначить любому ребёнку в любой момент, в том числе повторно или нескольким детям
  в разное время.
- **Скрыть / показать задание** — у каждого назначения есть переключатель «скрыть», который
  убирает задание из списка ребёнка, не удаляя его прогресс; в любой момент можно показать снова.
- **Импорт из файла** — во вкладке «Библиотека заданий» можно не только вставить JSON текстом,
  но и загрузить `.json` файл целиком.
- **3 попытки на задание** — ребёнок может исправить неверный ответ дважды; после третьей
  неверной попытки задание блокируется и показывается правильный ответ. Родитель/админ видят
  в панели прогресса количество использованных попыток по каждому заданию.
- **Просмотр ответов родителем** — во вкладке «Задания ребёнка» можно развернуть любое задание и
  увидеть сам вопрос, все попытки ребёнка и правильный ответ — как для проверки, так и чтобы
  помочь. Для заданий без автопроверки там же можно вручную отметить «верно» / «неверно».
- **Постраничное прохождение заданий** — ребёнок теперь видит одно задание на экране, может
  пропустить и вернуться к нему позже (точки-навигация показывают, что уже решено, что
  пропущено, а что ещё не открывали).
- **Награда за задание** — при создании/редактировании задания в библиотеке можно вписать
  награду (любой текст, на усмотрение родителя); она видна ребёнку на карточке задания, а
  родитель может отметить, что она выдана.
- **Аватарки** — каждый пользователь может загрузить своё фото в профиле.
- **Favicon** — админ может загрузить иконку приложения (вкладка «Настройки приложения»).
- **Мобильная адаптация** — интерфейс подстроен под маленькие экраны (телефон/планшет).

## Быстрый старт

1. Скопируйте файл с переменными окружения и заполните логин/пароль администратора:
   ```bash
   cp .env.example .env
   nano .env   # впишите логин/пароль администратора приложения
   ```

2. Запустите:
   ```bash
   docker compose up -d --build
   ```

3. Откройте в браузере: `http://localhost:3000` (или `http://<IP-компьютера-в-сети>:3000` с
   телефона/планшета в той же домашней сети).

4. Войдите под логином администратора (тем, что указали в `.env`) → вкладка **«Создать
   аккаунт»** → создайте аккаунт(ы) родителей и, при желании, сразу привяжите к ним детей.

5. Выйдите и войдите под только что созданным родительским логином → вкладка **«Мои дети»** →
   создайте аккаунт(ы) ребёнка (если ещё не создали через админку).

6. Там же, во вкладке **«Добавить задание»**, вставьте JSON с заданиями (см. ниже, как его
   получить) и отметьте, кому из ваших детей его назначить. Для проверки, что всё работает,
   можно сразу вставить содержимое `data/samples/sample-math.json` или `sample-russian.json`.

7. Войдите под логином ребёнка — задание появится в списке.

## Как добавлять реальные задания от учителя

Задания от учителя вы **не** обрабатываете руками — вы отправляете файл (Word/PDF/фото) в чат
любой языковой модели (Claude, ChatGPT и т.п.) вместе с заранее заготовленным промптом, модель
возвращает JSON, а вы просто вставляете этот JSON в панель родителя.

Полный текст промпта и описание формата (схемы) — в файле **`PARSING_PROMPT.md`**.

Коротко:
1. Открываете `PARSING_PROMPT.md`, копируете промпт целиком.
2. Вставляете его в чат с моделью, прикладываете файл учителя.
3. Получаете JSON, копируете его.
4. Вставляете в панели родителя → «Добавить задание» → «Импортировать».

Если модель вернула ошибку валидации — приложение покажет, что именно не так (например,
не хватает поля), это можно скопировать обратно модели с просьбой исправить.

## Типы заданий, которые поддерживает приложение

- Тест с одним правильным вариантом
- Тест с несколькими правильными вариантами
- Открытый ответ текстом (с автопроверкой по списку допустимых ответов)
- Открытый ответ числом (с допустимой погрешностью)
- Сопоставление пар (например, страна — столица)
- Заполнение пропусков в тексте (одно или несколько слов/букв)
- Творческие задания без единственного верного ответа — сохраняются с пометкой
  «ждёт проверки родителем» (автопроверка для них не применяется)

## Роли и права доступа

Три роли: **администратор**, **родитель**, **ребёнок**.

- **Администратор** — единственный аккаунт, который создаётся автоматически при первом запуске
  (из `ADMIN_USERNAME`/`ADMIN_PASSWORD` в `.env`). Дальше всё делается через интерфейс:
  - создаёт аккаунты родителей и детей (панель администратора → «Создать аккаунт»);
  - при создании ребёнка можно сразу привязать его к родителю, либо оставить непривязанным
    и назначить доступ позже;
  - вкладка «Доступ родителей к детям» — матрица чекбоксов: какой родитель видит прогресс
    какого ребёнка. Можно выдать одному ребёнку доступ сразу нескольким родителям (например,
    маме и папе);
  - может удалить любой аккаунт (кроме собственного);
  - может и сам зайти в панель родителя («Просмотр прогресса» в шапке) и смотреть прогресс
    любого ребёнка — по умолчанию администратору доступны все дети.
- **Родитель** — не может ничего этого делать сам за других родителей, только:
  - создавать аккаунты **своих** детей (вкладка «Мои дети» → «Добавить ребёнка»); ребёнок,
    созданный родителем, автоматически становится виден только этому родителю (пока
    администратор не откроет доступ кому-то ещё);
  - видеть прогресс и задания только тех детей, которых создал сам, либо тех, доступ к которым
    явно выдал администратор;
  - добавлять и удалять задания только для тех детей, которых видит, и только те задания,
    которые добавил сам (или которые может удалить администратор).
- **Ребёнок** — видит только список своих заданий и выполняет их; автопроверка — сразу видно,
  верно или нет, с пояснением (если оно было в задании).

Типичный сценарий на несколько семей на одном сервере: администратор заводит родителя для
каждой семьи, тот создаёт своих детей сам — семьи полностью изолированы друг от друга. Если
нужно, чтобы бабушка (отдельный родительский аккаунт) тоже видела прогресс — администратор
просто отмечает её в матрице доступа для нужного ребёнка, ничего пересоздавать не надо.

## Данные и бэкапы

Все данные (пользователи, задания, ответы) хранятся в SQLite-файле внутри Docker volume
`homework-data`, путь на хосте узнать можно командой:
```bash
docker volume inspect homework-app_homework-data
```
Для бэкапа скопируйте файл `app.db` из этого пути.

## Остановка / обновление

```bash
docker compose down          # остановить
docker compose up -d --build # пересобрать и запустить после изменений в коде
```

## Автосборка образа в GitHub Container Registry

В проекте есть готовый workflow `.github/workflows/docker-publish.yml`, который на каждый пуш
в `main`/`master` собирает Docker-образ и публикует его в GitHub Container Registry (ghcr.io) —
дальше образ можно просто скачивать на любом сервере без сборки на месте.

**Что нужно сделать один раз:**

1. Залейте проект в репозиторий на GitHub (публичный или приватный — неважно):
   ```bash
   git init
   git add .
   git commit -m "Initial commit"
   git branch -M main
   git remote add origin https://github.com/<ваш-логин>/<репозиторий>.git
   git push -u origin main
   ```
2. Больше ничего настраивать не нужно — workflow использует встроенный `GITHUB_TOKEN` для входа
   в ghcr.io, отдельный секрет создавать не надо. Убедитесь только, что в
   **Settings → Actions → General → Workflow permissions** выбрано
   *«Read and write permissions»* (обычно включено по умолчанию).
3. После первого пуша откройте вкладку **Actions** в репозитории — сборка запустится
   автоматически и займёт пару минут. Собранный образ появится во вкладке **Packages**
   (`ghcr.io/<ваш-логин>/<репозиторий>`).
4. По умолчанию новый пакет в GHCR приватный. Если хотите тянуть образ без логина на других
   машинах — зайдите в пакет → **Package settings** → **Change visibility** → **Public**. Если
   оставляете приватным, на сервере, где будете разворачивать, потребуется один раз выполнить:
   ```bash
   echo <personal access token с правом read:packages> | docker login ghcr.io -u <логин> --password-stdin
   ```

**Как это использовать:**
- При каждом пуше в `main` образ пересобирается и получает тег `latest`, а также
  `sha-<короткий-хеш-коммита>` — удобно, если нужно закрепиться на конкретной версии.
- Если хотите версии по семверу (`1.0.0`, `1.0`, `1`) — запушьте git-тег: `git tag v1.0.0 && git push --tags`.
- Собирается сразу под `linux/amd64` и `linux/arm64` (подходит и для обычного сервера, и для
  Raspberry Pi/Mac с ARM).
- Запустить готовый образ на любом другом компьютере (без клонирования репозитория и сборки):
  скопируйте `docker-compose.ghcr.yml` и `.env`, поправьте `image:` на ваш `ghcr.io/<логин>/<репо>`,
  затем:
  ```bash
  docker compose -f docker-compose.ghcr.yml up -d
  ```

Workflow можно также запустить вручную — вкладка **Actions** → *Build and publish Docker image*
→ **Run workflow**.

## Структура проекта

```
server.js              — Express-сервер, вся бизнес-логика и API
db.js                   — схема SQLite, создание пользователей при первом запуске
grading.js              — проверка ответов по типам заданий, валидация JSON при импорте
public/                 — фронтенд (обычный HTML/CSS/JS, без сборки)
  index.html            — страница входа
  child.html             — список заданий ребёнка
  assignment.html        — выполнение конкретного задания
  parent.html            — панель родителя (прогресс + импорт)
data/samples/           — примеры готовых JSON-заданий для проверки
.github/workflows/
  docker-publish.yml    — сборка и публикация Docker-образа в GitHub Container Registry
docker-compose.yml      — локальный запуск со сборкой образа на месте
docker-compose.ghcr.yml — запуск уже готового образа из ghcr.io
PARSING_PROMPT.md       — промпт и схема для превращения файла учителя в JSON
```
