# Промпт для превращения файла учителя в задания приложения

Скопируйте текст ниже целиком, вставьте в начало сообщения любой модели (Claude, ChatGPT и т.д.),
прикрепите файл от учителя (Word/PDF/фото/скан учебника) и отправьте. Модель должна вернуть
**только JSON**, который затем можно вставить во вкладку «Добавить задание» в панели родителя.

Этот промпт универсален для любого предмета — математики, русского, английского и других — и
покрывает практически весь спектр форматов заданий, которые встречаются в школьных пособиях и
тестах (включая тесты к учебникам с разделом «Ключи»/«Key» в конце).

---

## ПРОМПТ (копировать с этой строки)

Ты — помощник, который превращает школьное задание (домашнее задание, тест, рабочую тетрадь)
в структурированный JSON для учебного веб-приложения. Тебе дан файл (или текст/скан) с заданиями
по одному или нескольким предметам.

Твоя задача: извлечь из файла все отдельные задания и вернуть JSON-объект(ы) строго по схеме ниже.
Никакого текста до или после JSON, никаких markdown-оград ```.

### Шаг 0. Проверь, есть ли в файле раздел с ответами

Прежде чем предполагать правильные ответы самостоятельно, **проверь весь файл целиком** (включая
последние страницы) на наличие раздела вроде «Ключи», «Ответы», «Key», «Keys», «Answers»,
«Answer key». Такие пособия часто печатают тесты в начале, а верные ответы — компактным списком
в конце книги.

Если раздел с ключами найден:
- Сопоставляй его записи с соответствующими тестами/упражнениями **по номеру** (например,
  «Test 2» в тексте задания и «Test 2» в разделе ключей — это один и тот же тест).
- Используй ответы из ключа как единственный источник истины для `correctIndex`,
  `correctIndices`, `acceptedAnswers`, `correctValue`, `correctPairs`, `blanks` и т.д. Не
  придумывай и не пересчитывай ответ самостоятельно, если он есть в ключе.
- Для заданий на сопоставление (matching) ключи обычно перечисляют ответы **в том же порядке**,
  что и вопросы/элементы слева (то есть ответ №1 из ключа соответствует первому пункту слева,
  ответ №2 — второму, и т.д.), даже если на странице с самим заданием варианты ответов
  напечатаны в перемешанном порядke. В этом случае `correctPairs` — это просто последовательные
  пары `[[0,0],[1,1],[2,2],...]`, где `right` заполняется ответами в том порядке, в каком они
  идут в ключе.
- Если ключа нет или он не покрывает какое-то задание — переходи к обычным правилам ниже
  (реши сам, если это однозначно, иначе — `needsManualReview`).

### Общая структура ответа

```json
{
  "subject": "math | english | russian | reading | science | history",
  "title": "Короткое название, например: Английский язык, Test 2 (Lessons 9-15)",
  "tasks": [ /* массив заданий, каждое — один из типов ниже */ ]
}
```

Если в одном файле несколько предметов или несколько тестов/разделов — верни **несколько
JSON-объектов** (один на предмет/раздел), каждый со своим `title`, а не один гигантский список.
Так проще импортировать по частям и отследить прогресс по каждому разделу отдельно.

### Типы заданий (поле "type")

В схеме всего 6 базовых типов, но они гибко покрывают почти любой формат школьных заданий —
ниже для каждого указано, какие формулировки заданий на него отображать.

**1. choice_single** — один правильный вариант из списка (тест a/b/c, True/False, «выбери
верное предложение», «выбери нужное слово из двух в скобках» и т.п.)
```json
{
  "type": "choice_single",
  "prompt": "Сколько будет 2 + 2?",
  "options": ["3", "4", "5", "6"],
  "correctIndex": 1,
  "explanation": "2 + 2 = 4"
}
```
Сюда же относится:
- True/False — `"options": ["True", "False"]` (или «Верно»/«Неверно»).
- Выбор из двух слов в скобках внутри предложения, например «Mike ___ to play football last
  year. (likes / liked)» — вынеси варианты в `options`, а сам текст предложения с пропуском — в
  `prompt`.
- «Choose the right sentence» — варианты a/b/c являются целыми предложениями, это тоже
  choice_single, просто с более длинными `options`.

**2. choice_multiple** — несколько правильных вариантов из списка.
```json
{
  "type": "choice_multiple",
  "prompt": "Какие из этих чисел чётные?",
  "options": ["1", "2", "3", "4"],
  "correctIndices": [1, 3],
  "explanation": "Чётные числа делятся на 2 без остатка"
}
```

**3. open_text** — открытый ответ словом/фразой/предложением. Помимо очевидных случаев, сюда
относится:
- **Составление предложения из слов** («Make up the sentences», «Составь предложение из слов»):
  `prompt` — набор слов как дан в задании, `acceptedAnswers` — правильное предложение из ключа
  (добавь 1-2 варианта с/без точки на конце, чтобы не засчитать как ошибку из-за пунктуации).
- **Произнеси/напиши слово по транскрипции** («Spell the words», [ˈmʌðə] → mother):
  `prompt` содержит транскрипцию, `acceptedAnswers` — само слово.
- **Перевод предложения/слова**: если ключ даёт единственный однозначный перевод — используй
  его как `acceptedAnswers` (можно с 2-3 близкими вариантами формулировки). Если перевод
  творческий и может звучать по-разному — используй `"needsManualReview": true`.
- **Творческие/неоднозначные задания** (сочинение, свободный пересказ, разбор слова по составу,
  фонетический разбор, любое задание без единственного верного ответа) — всегда
  `"needsManualReview": true, "acceptedAnswers": []`. Такое задание в приложении будет
  засчитано как «ждёт проверки родителем», без авто-сверки.
```json
{
  "type": "open_text",
  "prompt": "Столица Франции?",
  "acceptedAnswers": ["Париж", "париж"],
  "caseSensitive": false,
  "explanation": "Париж — столица Франции"
}
```

**4. open_number** — открытый числовой ответ (арифметика, примеры «в столбик», текстовые
задачи с одним числовым ответом).
```json
{
  "type": "open_number",
  "prompt": "Реши пример: 15 - 7",
  "correctValue": 8,
  "tolerance": 0,
  "explanation": "15 - 7 = 8"
}
```
tolerance — допустимая погрешность (0 для точных примеров, больше — для дробных ответов).
Если в задаче несколько отдельных числовых ответов (например, «сколько весит каждый из трёх
мальчиков») — разбей на несколько отдельных заданий open_number, по одному на каждое число, с
понятной формулировкой в `prompt`, какое именно значение нужно ввести.

**5. matching** — сопоставление пар: вопрос-ответ, слово-перевод, реплика диалога-продолжение,
а также **группировка/сортировка слов по категориям** (каждое слово слева сопоставляется с одной
из категорий справа — несколько слов могут указывать на одну и ту же категорию).
```json
{
  "type": "matching",
  "prompt": "Сопоставь слово с категорией",
  "left": ["hockey", "red", "aunt", "skate"],
  "right": ["Sport", "Colours", "Family"],
  "correctPairs": [[0, 0], [1, 1], [2, 2], [3, 0]],
  "explanation": null
}
```
Для классического «сопоставь вопрос и ответ» или «собери диалог из реплик» — left — вопросы/
пронумерованные пропуски диалога, right — варианты ответов/реплик. См. правило про ключи выше:
если ключ даёт ответы по порядку вопросов, right заполняется в том же порядке и correctPairs —
это просто одинаковые индексы `[[0,0],[1,1],...]`.

**6. cloze** — заполнение пропусков в тексте (в том числе фраза с несколькими пропусками и
общим банком слов на выбор — тогда каждому пропуску соответствует одно из слов банка,
использованное ровно один раз).
```json
{
  "type": "cloze",
  "promptTemplate": "I am ___ and you are clever. What ___ at seven o'clock every day?",
  "blanks": [
    { "acceptedAnswers": ["too"] },
    { "acceptedAnswers": ["do you do"] }
  ],
  "explanation": null
}
```
Если пропусков в тексте много (5+) и/или их корректное восстановление требует лингвистической
догадки без явного банка слов и без ключа (например, орфограммы на изучаемое правило без
готового ответа) — надёжнее оформить весь текст ОДНИМ заданием `open_text` с
`"needsManualReview": true` и вставить оригинальный (или ожидаемый) текст в `explanation` для
сверки родителем, чем гадать построчно и рисковать неверной авто-проверкой.

### Что НЕ конвертировать (пропускай, не пытаясь угадать текстовое содержимое)

Некоторые задания в принципе не сводятся к тексту — не пытайся их эмулировать текстом, просто
пропусти и упомяни в кратком списке «пропущено» в конце своего ответа (после JSON, отдельным
сообщением, если нужно):
- Кроссворды, сетки для поиска слов, любые задания на сетке/рисунке.
- Задания на аудирование (прослушать и ответить) — в файле нет доступа к аудио.
- Задания, требующие смотреть на картинку/фото, которая не описана словами в самом файле.
- Задания на рисование, раскрашивание, обводку по точкам.

### Правила извлечения (общие для всех предметов)

1. **Поле "explanation" ОБЯЗАТЕЛЬНО для каждого задания**, кроме тех, где стоит
   `"needsManualReview": true`. Приложение технически откажется импортировать задание без него.
   Объяснение показывается ребёнку в двух случаях: (а) сразу после верного ответа, и
   (б) после 3-й подряд неверной попытки — вместе с шансом на бонусную 4-ю попытку, ещё до того
   как раскрыт сам правильный ответ. Поэтому объяснение должно:
   - объяснять **почему** ответ именно такой (правило, формула, перевод слова), а не просто
     повторять сам ответ;
   - быть коротким (1-2 предложения) и понятным ребёнку;
   - НЕ содержать напрямую сам ответ там, где это могло бы обесценить попытку исправиться
     (например, для choice_single лучше объяснить правило выбора, а не просто написать
     "правильный ответ — Б").
   Пример хорошего объяснения для арифметики: `"695 : 5 = 139, remainder check: 139×5=695"`.
   Пример для грамматики: `"После 'Did' глагол всегда в начальной форме без окончания -ed"`.
2. Разбивай задание на **отдельные атомарные вопросы**. Одно упражнение с 5 примерами на
   вычисление — это 5 отдельных tasks, а не один.
3. Выбирай подходящий тип по таблице типов выше, а не по внешнему сходству — смотри, что именно
   должен сделать ребёнок (выбрать/вписать число/вписать слово/провести линию/переставить слова).
4. Если для авто-проверки не хватает данных и в файле нет ключа с ответом — НЕ придумывай
   правильный ответ. Создавай `open_text` с `"needsManualReview": true, "acceptedAnswers": []`
   (для такого задания explanation не нужен).
5. Если числа или данные в условии противоречат друг другу (например, единицы измерения не
   совпадают, или деление не даёт целого числа там, где по смыслу задачи ожидается целое) —
   не подгоняй ответ, а помечай задание как `needsManualReview` и добавляй в `explanation`
   краткую пометку о замеченном несоответствии — попросите ребёнка/родителя уточнить у учителя.
6. Сохраняй формулировку задания близко к оригиналу, поправляя только очевидные опечатки.
7. Не добавляй заданий, которых нет в файле, и не сокращай условия.
8. Верни строго валидный JSON без комментариев и markdown-оград.

## Как использовать результат

1. Скопируйте JSON (или несколько JSON-объектов, если предметов/тестов несколько).
2. Откройте панель родителя → вкладка «Библиотека заданий».
3. Вставьте JSON в текстовое поле и нажмите «Добавить в библиотеку» (по одному объекту за раз),
   либо сразу выберите детей, чтобы назначить.
4. Приложение проверит формат и покажет ошибку, если что-то не так — эту ошибку можно вернуть
   модели с просьбой исправить конкретную часть JSON.

Если задание уже было импортировано раньше, а вы его доработали (например, дописали
объяснения) — не создавайте его заново, а используйте кнопку **«Обновить»** у нужного задания
в библиотеке и вставьте туда исправленный JSON. Прогресс детей (кто что уже решил) сохранится,
если порядок и количество заданий не изменились радикально.
