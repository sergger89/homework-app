# Домашние задания — веб-приложение

Приложение для выполнения ребёнком заданий по школьным предметам в браузере, с автопроверкой
и отслеживанием прогресса родителем. Работает в Docker, все данные хранятся локально.

## Маскот на экране постоянно (плавающий виджет)

Раньше реакции маскота (`showMascotToast`) были одноразовыми всплывающими карточками,
которые появлялись и исчезали. Теперь вместо этого — **один постоянный плавающий
виджет** в правом нижнем углу экрана:

- Автоматически появляется на всех страницах ребёнка, кроме читалки (не мешает чтению)
  и `shop.html` (там уже есть свой постоянный виджет прямо в контенте страницы —
  показывать оба сразу было бы избыточно).
- Реагирует на те же события, что и раньше (верный/неверный ответ, открытие черновика,
  избранная книга, смена пароля и т.д.) — просто теперь через один и тот же постоянно
  видимый персонаж, а не отдельные всплывающие карточки.
- **Кнопка 🦉 рядом** — скрыть/показать виджет по желанию. Выбор запоминается в
  `localStorage`, переживает перезагрузку страницы. Пока скрыт, маскот всё равно молча
  меняет выражение при реакциях (просто без речевого пузыря) — не отстаёт от контекста,
  когда его снова покажут.
- Реализация - `initFloatingMascot()` / `setFloatingMascotHidden()` /
  `showMascotToast()` в `public/js/common.js`; авто-инициализация - в самом низу того
  же файла, с проверкой роли через `/api/me`.

## Анимированный слоистый маскот (интеграция в приложение)

Прежний маскот — 12 отдельных плоских стикеров (по одному на эмоцию). Теперь в
`public/mascot-layers/` живёт новый набор — тело, 4 позы, 6 вариантов глаз, 6 ртов,
2 румянца, 4 эффекта (слёзы разделены на левую/правую по отдельности) — собранный по
кускам через Nano Banana / ChatGPT и выверенный вручную (реальные пропорции, положение
глаз/рта под каждую конкретную позу, отдельные капли слёз под каждый глаз и т.д.).

- **`public/js/mascot-render.js`** — вся логика композиции слоёв в один узел: считает
  реальный размер и позицию каждого слоя из измеренных констант (см. код), а не
  фиксированными процентами, чтобы не «плыло» при разных позах.
- **`MASCOT_EMOTION_MAP`** в этом же файле — таблица перевода прежних 12 ключей эмоций
  (`joy`, `sadness`, `wink` и т.п. — те, что уже использовались по всему приложению) в
  конкретную комбинацию pose+eyes+mouth+blush+effect. Все существующие вызовы
  `mascot.say(text, 'joy')` / `showMascotToast(text, 'sadness')` по всему коду **не
  менялись** — просто теперь под капотом рисуется не один стикер, а живая композиция.
- **Что обновилось:** постоянный виджет маскота в магазине (`createMascotWidget`) и
  всплывающие реакции на действия (`showMascotToast`, используется в assignment.html,
  books.html, profile.html) — теперь показывают анимированного слоистого маскота.
- **Что осталось прежним:** маленькая (34px) иконка настроения на главной ребёнка и
  книжной полке — сознательно оставлена на старой плоской системе (`mascotSrc()`),
  потому что при таком крошечном размере тонкая слоистая композиция не читается и
  выглядела бы мутно; для статичного индикатора настроения плоский стикер надёжнее.
- Автоморгание в анимированном виджете включается только когда текущие глаза «открытые»
  (`eyes_neutral`, `eyes_surprised`, `eyes_sad`, `eyes_angry`) — не моргает поверх уже
  закрытых/особых состояний.

## Русский язык без бумаги: разбор предложения и разбор слова по составу

Два новых типа заданий с **полной автопроверкой** (раньше такое можно было делать только на
бумаге и проверять руками):

- **`sentence_parse`** — разбор предложения по членам. Ребёнок выделяет слово(-а) в предложении
  и нажимает нужный член: подлежащее (сплошная черта), сказуемое (двойная), определение
  (волнистая), дополнение (пунктир), обстоятельство (точки — используется как практичная замена
  традиционного пунктир-тире, которое не поддерживается стандартным CSS). Проверяется точное
  совпадение разбора со всем предложением, слово в слово.
- **`word_composition`** — разбор слова по составу. Ребёнок выделяет буквы и нажимает нужную
  часть слова: приставка/корень/соединительная гласная/суффикс/окончание/постфикс (поддерживает
  и сложные слова с несколькими корнями). Отдельная кнопка «□ Нулевое окончание» для слов без
  окончания. Части слова подсвечиваются разными цветами прямо по буквам.
- **Проверочные слова в `cloze`** — у любого пропущенной буквы можно попросить дополнительно
  вписать проверочное слово (`"needsCheckWord": true` на нужном пропуске в JSON) — появляется
  отдельное поле рядом с пропуском. Само проверочное слово не сверяется автоматически (это
  на усмотрение родителя при ручной проверке), но сохраняется и видно в панели ревью.

Оба новых типа задокументированы в `PARSING_PROMPT.md` (разделы 8 и 9) — при следующей генерации
заданий модель будет использовать их вместо расплывчатого «спиши в тетрадь» для этих упражнений.

**Обновление:** все 115 заданий «разбери слово по составу» в `summer-russian-full.json` (43 дня)
теперь проверяются **автоматически** — разобрал каждое слово вручную и проверил, что разбор
побуквенно совпадает с самим словом (без пропусков/задвоений). Если ребёнок не согласен с
автопроверкой — есть кнопка «🚩 Отправить на проверку» (см. раздел про геймификацию ниже),
которая передаёт конкретный ответ родителю на ручную сверку — так что даже если где-то в разборе
закралась ошибка, это не станет тупиком.

## Геймификация 2: попытки за монету, серебро, маскот везде, сессии

- **Докупить попытки** — после исчерпания обычных 3 (+1 бонусной) попыток можно за 1 золотую
  монету купить ещё 3, и так можно несколько раз подряд, пока не закончатся монеты или ребёнок
  не решит остановиться. Как только текущая (последняя доступная) попытка окажется неверной —
  раскрывается правильный ответ, и докупить больше нельзя (в интерфейсе есть предупреждение об
  этом прямо у кнопки).
- **Серебряные монеты** — отдельная валюта, начисляется в том же количестве (10), что и золото,
  за каждое верно решённое задание. Тратится только на еду для маскота во вкладке «Покормить»
  магазина. 6 лакомств уже добавлены по умолчанию (Медовые кристаллы, Ягодный смузи, Звёздное
  печенье, Солнечные крендельки, Радужное мороженое, Праздничный пирог) — родитель/админ может
  добавить свои через форму (выбрать тип «Лакомство»).
- **Голод маскота** — шкала 0-100%, сама снижается со временем (по умолчанию — полностью «проголодается»
  за **4 часа** без кормления; родитель/админ может настроить эту скорость отдельно для каждого
  ребёнка в магазине, раздел «⏱️ Скорость голода маскота»), кормление сразу восстанавливает — без
  участия родителя, в отличие от обычных наград. Уровень голода теперь влияет на то, **какое у маскота настроение
  по всему приложению**: сытый — радостный, голодный — грустный/скучающий, и так на главной
  ребёнка, книжной полке и в самом магазине.
- **Маскот на всех страницах ребёнка (кроме читалки)** — своя реакция на: открытие черновика,
  переход к следующему заданию (с защитой от спама - не чаще раза в 4 секунды при частых кликах,
  кроме по-настоящему важных событий вроде верного ответа), завершение всего задания целиком,
  добавление книги в избранное, загрузку аватарки, смену пароля. Everywhere - через общие функции
  `showMascotToast()` / `createMascotWidget()` в `public/js/common.js`.
- **Смена отображаемого имени** — теперь это делает администратор (панель → таблица
  пользователей → «Изменить имя»), по запросу родителя/ребёнка, не самообслуживание.
- **Сессии переживают перезапуск сервера** — раньше сессии хранились только в памяти процесса
  Node.js, и любой рестарт контейнера (деплой, обновление, краш) разлогинивал вообще всех, даже
  если кука в браузере была ещё действительна 30 дней. Теперь сессии хранятся в той же SQLite
  базе (пакет `better-sqlite3-session-store`) и переживают перезапуски.

## Геймификация: монеты, магазин, ручная проверка по запросу

- **Монеты** — фиксированные 10 монет за каждое верно решённое задание (автопроверка или
  ручная оценка родителем — не важно, начисляется один раз за задание). Баланс виден ребёнку
  на главной и внутри задания, всплывающее уведомление «🪙 +10» при верном ответе.
- **Магазин** (`/shop.html`) — родитель/админ заводит товары (название, описание, цена в
  монетах, эмодзи-иконка): время на телефоне, сладость, подарок — что угодно. Ребёнок покупает
  за монеты; покупка висит в статусе «⏳ Ожидает выдачи», пока родитель не отметит «Выдано»
  (как и с наградой за задание). Товары от админа видны всем детям, товары от родителя — только
  его собственным (та же логика видимости, что у книг).
- **Маскот** — собственный персонаж на 12 эмоций (`public/mascot/*.png`: joy, sadness, anger,
  surprise, disappointment, boredom, wink, admiration, disgust, horror, kiss, fun), с CSS-анимацией
  (bounce/shake) и речевым пузырём:
  - в **магазине** — постоянный виджет: приветствует при входе (радость, если есть монеты /
    лёгкое разочарование, если пусто), радуется удачной покупке, мягко подбадривает при
    нехватке монет, комментирует статус во вкладке истории покупок (скука, если что-то ещё не
    выдано / веселье, если всё получено);
  - в **задании** — ненавязчивая всплывающая реакция в левом нижнем углу (не мешает основному
    контенту): радость при верном ответе (с вариациями фразы), удивление при первой ошибке,
    подмигивание при выдаче бонусной подсказки, грусть при исчерпании попыток, скука при отправке
    на ручную проверку;
  - на **главной странице ребёнка** — маленькая (34px) статичная иконка рядом с приветствием,
    без пузыря — просто дружелюбное присутствие, не отвлекает.
  Список эмоций и подбор картинки — в `public/js/common.js` (`MASCOT_EMOTIONS`,
  `createMascotWidget`, `showMascotToast`), общие для всех страниц. Прежний механизм загрузки
  через `POST /api/admin/mascot` (одна картинка вместо favicon) по-прежнему на месте, но сейчас
  не используется — можно задействовать, если понадобится сменить персонажа целиком.
- **«Отправить на проверку»** — у ребёнка после любого автопроверенного ответа (кроме заданий,
  и так идущих на ручную проверку) есть кнопка «🚩 Отправить на проверку», если он не согласен
  с автооценкой. Попадает в общий список у родителя вместе с обычными ручными заданиями.
- **«Ожидают проверки»** — новый раздел у родителя/админа (кнопка в шапке с красным счётчиком,
  обновляется каждые 30 сек) — единый список всего, что требует внимания: и задания без
  автопроверки, и то, что сам ребёнок попросил перепроверить, по всем детям сразу. Отметить
  «верно/неверно» можно прямо из этого списка.
- **Прогресс родителя** упрощён: таблица «Попытки по заданиям» убрана (дублировала другую
  информацию), «Последние ответы» теперь на первом месте, список компактный (по 8 строк,
  «Показать ещё» для остального), клик по строке разворачивает сам вопрос и ответ ребёнка на
  месте, без перехода на другую вкладку.

## Что добавилось во второй итерации доработок

- **Бонусная попытка** — после 3-й неверной попытки показывается объяснение (без самого
  ответа) и даётся ещё один, последний шанс. Если и он неверный — тогда показывается правильный
  ответ. Поле `explanation` в JSON задания теперь **обязательно** для всех автопроверяемых типов
  (кроме `needsManualReview: true`) — без него приложение откажется импортировать задание.
- **Обновление задания без потери прогресса** — в библиотеке заданий у каждого задания есть
  кнопка «Обновить JSON»: можно вставить исправленную версию (например, дописали объяснения),
  и прогресс детей, ответивших на совпадающие по номеру задания, сохранится.
- **Черновик прямо в задании** — кнопка «✏️ Черновик» открывает попап с рисованием (мышью на ПК,
  пальцем на телефоне/планшете): выбор цвета, маркер-выделение, ластик, отмена/возврат, стереть
  всё. Черновик сохраняется на сервере отдельно по каждому заданию — можно закрыть и вернуться
  позже, дорисовать. Родитель/админ тоже может посмотреть черновик ребёнка (через API).
- **Книжная полка (epub)** — общая для всех детей родителя (или для всех детей приложения, если
  загрузил админ); родитель/админ загружает .epub-файл (до 80 МБ) и, по желанию, обложку. Ребёнок
  читает книгу прямо в браузере (постраничная читалка на основе epub.js, работает офлайн — сама
  библиотека лежит в проекте, не грузится с внешних серверов), может добавить книгу в избранное,
  прогресс чтения (%, последняя страница) сохраняется и виден и ребёнку, и родителю/админу. На
  полке у ребёнка три вкладки: «Общая», «Продолжить чтение» (сортировка по последней открытой) и
  «Избранное». Прямо в читалке можно выделить текст пальцем/мышью, выбрать цвет выделения и
  дописать свою мысль — получится заметка; вкладка «Заметки» рядом со счётчиком страниц показывает
  все заметки по книге с кнопкой «Перейти на страницу» (переход не сбивает сохранённый прогресс
  чтения — во время просмотра заметки виден баннер «Вернуться к чтению»). Родитель/админ видят
  заметки ребёнка (в режиме просмотра, без права добавлять/удалять).

**Важный нюанс:** поскольку объяснение стало обязательным, все примеры в `data/samples/` были
обновлены — там, где объяснения не было, оно сгенерировано автоматически (простой шаблон вида
«Верный вариант: …» / «Проверь вычисление — должно получиться …»). Это рабочий, но не самый
качественный вариант объяснений для сотен заданий из английского пособия и летних заданий —
при желании их стоит доработать вручную или через модель повторно.

## Новое в первой итерации доработок

- **Смена ролей после создания** — админ может в любой момент поменять роль любого пользователя
  (родитель → админ, админ → родитель и т.д.) прямо из панели администратора. Нельзя разжаловать
  последнего администратора.
- **Пароли**: у каждого пользователя есть страница «Профиль» для смены своего пароля; админ может
  сбросить пароль любому пользователю. Пароль самого админа можно сбросить и через переменную
  окружения `RESET_ADMIN_PASSWORD=true` (см. ниже) — на случай, если забыли пароль и не можете
  зайти в интерфейс вообще.
- **Библиотека заданий** — импорт задания больше не привязан жёстко к конкретному ребёнку:
  задание сначала попадает в общую библиотеку (вкладка «Библиотека заданий» у родителя), а затем
  его можно назначить любому ребёнку в любой момент, в том числе повторно или нескольким детям
  в разное время.
- **Скрыть / показать задание** — у каждого назначения есть переключатель «скрыть», который
  убирает задание из списка ребёнка, не удаляя его прогресс; в любой момент можно показать снова.
- **Импорт из файла** — во вкладке «Библиотека заданий» можно не только вставить JSON текстом,
  но и загрузить `.json` файл целиком.
- **3 попытки на задание** — ребёнок может исправить неверный ответ дважды; после третьей
  неверной попытки задание блокируется и показывается правильный ответ. Родитель/админ видят
  в панели прогресса количество использованных попыток по каждому заданию.
- **Просмотр ответов родителем** — во вкладке «Задания ребёнка» можно развернуть любое задание и
  увидеть сам вопрос, все попытки ребёнка и правильный ответ — как для проверки, так и чтобы
  помочь. Для заданий без автопроверки там же можно вручную отметить «верно» / «неверно».
- **Постраничное прохождение заданий** — ребёнок теперь видит одно задание на экране, может
  пропустить и вернуться к нему позже (точки-навигация показывают, что уже решено, что
  пропущено, а что ещё не открывали).
- **Награда за задание** — при создании/редактировании задания в библиотеке можно вписать
  награду (любой текст, на усмотрение родителя); она видна ребёнку на карточке задания, а
  родитель может отметить, что она выдана.
- **Аватарки** — каждый пользователь может загрузить своё фото в профиле.
- **Favicon** — админ может загрузить иконку приложения (вкладка «Настройки приложения»).
- **Мобильная адаптация** — интерфейс подстроен под маленькие экраны (телефон/планшет).

## Быстрый старт

1. Скопируйте файл с переменными окружения и заполните логин/пароль администратора:
   ```bash
   cp .env.example .env
   nano .env   # впишите логин/пароль администратора приложения
   ```

2. Запустите:
   ```bash
   docker compose up -d --build
   ```

3. Откройте в браузере: `http://localhost:3000` (или `http://<IP-компьютера-в-сети>:3000` с
   телефона/планшета в той же домашней сети).

4. Войдите под логином администратора (тем, что указали в `.env`) → вкладка **«Создать
   аккаунт»** → создайте аккаунт(ы) родителей и, при желании, сразу привяжите к ним детей.

5. Выйдите и войдите под только что созданным родительским логином → вкладка **«Мои дети»** →
   создайте аккаунт(ы) ребёнка (если ещё не создали через админку).

6. Там же, во вкладке **«Добавить задание»**, вставьте JSON с заданиями (см. ниже, как его
   получить) и отметьте, кому из ваших детей его назначить. Для проверки, что всё работает,
   можно сразу вставить содержимое `data/samples/sample-math.json` или `sample-russian.json`.

7. Войдите под логином ребёнка — задание появится в списке.

## Как добавлять реальные задания от учителя

Задания от учителя вы **не** обрабатываете руками — вы отправляете файл (Word/PDF/фото) в чат
любой языковой модели (Claude, ChatGPT и т.п.) вместе с заранее заготовленным промптом, модель
возвращает JSON, а вы просто вставляете этот JSON в панель родителя.

Полный текст промпта и описание формата (схемы) — в файле **`PARSING_PROMPT.md`**.

Коротко:
1. Открываете `PARSING_PROMPT.md`, копируете промпт целиком.
2. Вставляете его в чат с моделью, прикладываете файл учителя.
3. Получаете JSON, копируете его.
4. Вставляете в панели родителя → «Добавить задание» → «Импортировать».

Если модель вернула ошибку валидации — приложение покажет, что именно не так (например,
не хватает поля), это можно скопировать обратно модели с просьбой исправить.

## Типы заданий, которые поддерживает приложение

- Тест с одним правильным вариантом
- Тест с несколькими правильными вариантами
- Открытый ответ текстом (с автопроверкой по списку допустимых ответов)
- Открытый ответ числом (с допустимой погрешностью)
- Сопоставление пар (например, страна — столица)
- Заполнение пропусков в тексте (одно или несколько слов/букв)
- Творческие задания без единственного верного ответа — сохраняются с пометкой
  «ждёт проверки родителем» (автопроверка для них не применяется)

## Роли и права доступа

Три роли: **администратор**, **родитель**, **ребёнок**.

- **Администратор** — единственный аккаунт, который создаётся автоматически при первом запуске
  (из `ADMIN_USERNAME`/`ADMIN_PASSWORD` в `.env`). Дальше всё делается через интерфейс:
  - создаёт аккаунты родителей и детей (панель администратора → «Создать аккаунт»);
  - при создании ребёнка можно сразу привязать его к родителю, либо оставить непривязанным
    и назначить доступ позже;
  - вкладка «Доступ родителей к детям» — матрица чекбоксов: какой родитель видит прогресс
    какого ребёнка. Можно выдать одному ребёнку доступ сразу нескольким родителям (например,
    маме и папе);
  - может удалить любой аккаунт (кроме собственного);
  - может и сам зайти в панель родителя («Просмотр прогресса» в шапке) и смотреть прогресс
    любого ребёнка — по умолчанию администратору доступны все дети.
- **Родитель** — не может ничего этого делать сам за других родителей, только:
  - создавать аккаунты **своих** детей (вкладка «Мои дети» → «Добавить ребёнка»); ребёнок,
    созданный родителем, автоматически становится виден только этому родителю (пока
    администратор не откроет доступ кому-то ещё);
  - видеть прогресс и задания только тех детей, которых создал сам, либо тех, доступ к которым
    явно выдал администратор;
  - добавлять и удалять задания только для тех детей, которых видит, и только те задания,
    которые добавил сам (или которые может удалить администратор).
- **Ребёнок** — видит только список своих заданий и выполняет их; автопроверка — сразу видно,
  верно или нет, с пояснением (если оно было в задании).

Типичный сценарий на несколько семей на одном сервере: администратор заводит родителя для
каждой семьи, тот создаёт своих детей сам — семьи полностью изолированы друг от друга. Если
нужно, чтобы бабушка (отдельный родительский аккаунт) тоже видела прогресс — администратор
просто отмечает её в матрице доступа для нужного ребёнка, ничего пересоздавать не надо.

## Если не загружаются книги/большие файлы (413 или обрыв без ответа)

Приложение само разрешает файлы до 80МБ (epub, аватарки, favicon, json) — это уже проверено и
работает на уровне Node/Express. Если загрузка книги (или другого крупного файла) всё равно не
проходит, а мелкие файлы (аватарки, JSON-задания) грузятся нормально — почти наверняка дело в
**reverse proxy / ingress перед приложением**, у которого свой, более строгий лимит на размер
тела запроса (у nginx по умолчанию это часто всего 1МБ).

- **nginx-ingress в Kubernetes** — добавьте аннотацию на Ingress (или в values Helm-чарта):
  ```yaml
  nginx.ingress.kubernetes.io/proxy-body-size: "100m"
  ```
- **обычный nginx перед Docker-контейнером** — в конфиге сервера/location:
  ```
  client_max_body_size 100m;
  ```
- **Traefik** — мидлварь `buffering` с `maxRequestBodyBytes`, либо `spec.transport` в IngressRoute.

Как отличить: если запрос вообще не доходит до приложения, интерфейс покажет «Загрузка прервалась,
не дойдя до сервера» — это почти всегда прокси/ingress. Если дошёл, но был отклонён самим
приложением из-за размера, будет `HTTP 413: file_too_large` — тогда дело либо в лимите 80МБ в
`server.js` (можно поднять), либо в проксировании выше по цепочке.

## Автосборка образа в GitHub Container Registry

В репозитории (на верхнем уровне, рядом с папкой `homework-app/`) есть готовый workflow
`.github/workflows/docker-publish.yml`, который на каждый пуш в `main`/`master` (если изменения
затронули `homework-app/**`) собирает Docker-образ и публикует его в GitHub Container Registry
(ghcr.io) — дальше образ можно просто скачивать на любом сервере без сборки на месте.

**Что нужно сделать один раз:**

1. Заведите один репозиторий на GitHub и положите в его корень **обе** папки — `homework-app/`
   и, если нужен Android-клиент, `android-client/` — вместе с папкой `.github/` (все три лежат
   рядом, ничего никуда переносить не нужно, workflow уже настроены на такое расположение):
   ```bash
   git init
   git add .
   git commit -m "Initial commit"
   git branch -M main
   git remote add origin https://github.com/<ваш-логин>/<репозиторий>.git
   git push -u origin main
   ```
2. Больше ничего настраивать не нужно — workflow использует встроенный `GITHUB_TOKEN` для входа
   в ghcr.io, отдельный секрет создавать не надо. Убедитесь только, что в
   **Settings → Actions → General → Workflow permissions** выбрано
   *«Read and write permissions»* (обычно включено по умолчанию).
3. После первого пуша откройте вкладку **Actions** в репозитории — сборка запустится
   автоматически и займёт пару минут. Собранный образ появится во вкладке **Packages**
   (`ghcr.io/<ваш-логин>/<репозиторий>`).
4. По умолчанию новый пакет в GHCR приватный. Если хотите тянуть образ без логина на других
   машинах — зайдите в пакет → **Package settings** → **Change visibility** → **Public**. Если
   оставляете приватным, на сервере, где будете разворачивать, потребуется один раз выполнить:
   ```bash
   echo <personal access token с правом read:packages> | docker login ghcr.io -u <логин> --password-stdin
   ```

**Как это использовать:**
- При каждом пуше в `main` образ пересобирается и получает тег `latest`, а также
  `sha-<короткий-хеш-коммита>` — удобно, если нужно закрепиться на конкретной версии.
- Если хотите версии по семверу (`1.0.0`, `1.0`, `1`) — запушьте git-тег: `git tag v1.0.0 && git push --tags`.
- Собирается сразу под `linux/amd64` и `linux/arm64` (подходит и для обычного сервера, и для
  Raspberry Pi/Mac с ARM).
- Запустить готовый образ на любом другом компьютере (без клонирования репозитория и сборки):
  скопируйте `docker-compose.ghcr.yml` и `.env`, поправьте `image:` на ваш `ghcr.io/<логин>/<репо>`,
  затем:
  ```bash
  docker compose -f docker-compose.ghcr.yml up -d
  ```

Workflow можно также запустить вручную — вкладка **Actions** → *Build and publish Docker image*
→ **Run workflow**.

## Структура проекта

```

grading.js              — проверка ответов по типам заданий, валидация JSON при импорте

  index.html            — страница входа
  child.html             — список заданий ребёнка
  assignment.html        — выполнение задания (визард с попытками, черновиком, наградой)
  parent.html            — панель родителя (прогресс, ревью ответов, библиотека, дети)
  admin.html             — панель администратора (пользователи, роли, доступ, настройки)
  profile.html           — смена пароля и аватарки (общая для всех ролей)
  books.html             — книжная полка
  reader.html            — читалка epub (на основе epub.js)
  js/scratchpad.js       — модуль рисования (черновик)
  vendor/                — epub.js и jszip, встроены локально (без внешних CDN)
data/samples/           — примеры готовых JSON-заданий для проверки
.github/workflows/
  docker-publish.yml    — сборка и публикация Docker-образа в GitHub Container Registry
docker-compose.yml      — локальный запуск со сборкой образа на месте
docker-compose.ghcr.yml — запуск уже готового образа из ghcr.io
PARSING_PROMPT.md       — промпт и схема для превращения файла учителя в JSON
```
